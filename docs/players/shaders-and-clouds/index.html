Shader settings and clouds

Change shader #define settings and the GLSL version while the game runs, add post-processing effects, and decide where clouds appear - with two ini files.

Two ready-made mods of the SDK (shader_config and cloud_control) are set up with a plain text file. You edit it, save it, and the game follows within a second - no restart and no reloading of the save.

Not tried in the game yet

Both mods are built and tested against the game files, but they have not been run in a live game yet. Please report what you see.

Shader settings: shader_config#

The game builds every shader from text: it writes #version 330 at the top and adds a #define line for each graphics setting. Shader packs use #define for their own settings too. With shader_config you change these lines yourself.

  1. Install the mod and start the game once. It makes the file <Stormworks>\mods\shader_config\shader_config.ini with explanations.
  2. Open it, change a line, save. The shaders are rebuilt right away. Ctrl+F8 in the game rebuilds by hand.
  3. Look in the mod log (%TEMP%\stormworks_mods.log, lines shader_config:) for the result. If the driver did not accept a shader, its message is there with the file name.
ini
[general]
; 0 = the game's (330). 460 = OpenGL 4.6 features, if your graphics driver has them
glsl_version = 460

[defines]
; in every shader. A #define of the same name in the game or in a shader file is replaced
MY_PACK_SSR = 1
; "!" removes the line: the shader takes its #else / #ifndef branch
MY_PACK_BLOOM = !

[light.glslf]
; only in this one file
MY_PACK_FOG_STEPS = 32

[.glslf]
; only in fragment shaders ([.glslv] vertex, [.glslg] geometry)
MY_PACK_DEBUG = 0
  • A shader file you edit in rom\graphics\shaders (or that a shader mod lays over it) is also picked up when you save it.
  • glsl_version = 0 goes back to the game's version. If a version is too high for your driver, every shader fails and the log says so: set it back and save.
  • Shader authors can check their files before they ship them: swshadercheck --version 460 <shader folder> builds every shader with the local driver.

Post-processing effects: shader_config#

The same mod can also draw effects over the finished picture at the end of every frame: sharpening, colour grading, vignette, film grain - or anything you write yourself as a small shader.

Built-in effects. List them in the [postfx] section of shader_config.ini, in the order they should run. Their settings go into a section [postfx:<name>]:

ini
[postfx]
enabled = 1
presets = sharpen, saturation, vignette

[postfx:sharpen]
u_amount = 0.4            ; 0 = off, 1 = strong
[postfx:saturation]
u_amount = 1.2            ; 0 = grey, 1 = unchanged
[postfx:vignette]
u_amount = 0.35
u_softness = 0.45
PresetWhat it doesSettings (default)
vignettedarker cornersu_amount 0.35, u_softness 0.45
sharpensharper edgesu_amount 0.4
saturationcolour strengthu_amount 1.2
contrastcontrast and brightnessu_contrast 1.1, u_brightness 0.0
tintcolour gradeu_color 1.0 0.97 0.92, u_amount 1.0
grainfilm grainu_amount 0.04
chromatic_aberrationcolour fringes at the edgesu_amount 1.5 (pixels)

Your own effects. Every *.glsl file in <Stormworks>\mods\shader_config\postfx is an effect (the folder has a README.txt). A number at the start of the name is the order: 10_grade.glsl runs before 20_vignette.glsl. Save a file and it is used within a second; delete it and it is gone. A file only needs one function:

glsl
uniform float u_amount = 0.5;          // a setting with its default; [postfx:10_grey] u_amount = 0.8 in the ini changes it
vec4 effect(vec4 color, vec2 uv) {
    float grey = dot(color.rgb, vec3(0.299, 0.587, 0.114));
    return vec4(mix(color.rgb, vec3(grey), u_amount), 1.0);
}

Ready to use in every effect: u_scene (the picture so far), u_resolution (its size in pixels), u_time (seconds), u_frame, v_uv, scene(uv) (the picture at a point) and texel() (one pixel in uv units). A first line #version 460 uses a newer GLSL.

  • Ctrl+F7 switches all effects off and on - handy to compare.
  • If the driver does not accept a file, the log (%TEMP%\stormworks_mods.log) has its message with the line number of your file. The other effects keep running.
  • The effects see the final picture: after the game's tonemap and anti-aliasing, 8 bits per channel, with the HUD and menus on it. There is no depth and no HDR here; an effect before the tonemap is not possible yet.

Clouds: cloud_control#

The game keeps clouds in a circle around the camera (3000 m) and makes a new one whenever one ends. cloud_control decides where those new clouds may appear.

  1. Install the mod and start the game once. It makes <Stormworks>\mods\cloud_control\cloud_control.ini.
  2. Edit and save it. The clouds in the sky are made again with your rules. Ctrl+F9 puts one cloud above you.
ini
[clouds]
max_clouds = 150          ; -1 = the game's number
field_radius = 0          ; metres around the camera in which clouds live, 0 = the game's 3000
min_height = 500          ; metres; 0 and 0 = the game's 300 to 1000
max_height = 900
shape = 0                 ; 0 = random, 2 to 8 = always meshes/cloud_02 .. cloud_08

[only_in]
area = 0, 0, 20000        ; x, z, radius: clouds ONLY in these circles (any number of lines)

[never_in]
area = 2000, -1500, 3000  ; x, z, radius: NO clouds here

[spawn]
cloud = 500, 700, 500     ; x, height, z: one cloud there every time you save
  • Positions are world metres as in the map and getPlayerPos (x east, z north).
  • Clouds only exist near the camera: an only_in area far away gets its clouds when you come near it. A [spawn] cloud must be within field_radius of the camera.
  • Clouds are drawn by each player's own game. In multiplayer every player sees the sky of their own settings.

For developers#

Both mods are thin layers over headers: sw/shader_build.hpp (define(), glsl_version(), rebuild(), status()), sw/postfx.hpp (add_file(), add_folder(), add_preset(), set(), effects()) and sw/clouds.hpp (set_rules(), spawn_at(), respawn_all(), info()). Their sources are src/shader_config_mod.cpp and src/cloud_control_mod.cpp in the SDK.
