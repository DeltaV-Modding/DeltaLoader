Changelog

Everything that changed in the DeltaLauncher, newest first.

All notable changes to the DeltaLauncher (formerly DeltaV Modding Launcher).

1.0.12 - 2026-11-06#

Added#

  • Settings: Debug start (RenderDoc). For tools that have to start the game themselves (RenderDoc, PIX, a debugger). Press it, then start Stormworks in the tool: the mod folders (shaders) are laid over rom first, and the version patch and the switched-on mods are loaded into the game when it appears. The originals are restored when the game ends. Do not start the launcher itself inside RenderDoc.

1.0.11 - 2026-11-05#

Changed#

  • Self update: a new launcher is installed silently (/S /UPDATE /R), without the setup wizard, and starts again by itself.
  • Discord Rich Presence is on by default; the key is written to settings.json at the first start. It can still be switched off in Settings.

Added#

  • Injector 1.0.6 is built into the launcher together with the version patch. A fresh install needs no download, and an older installed injector (for example 1.0.0) is replaced at the start of the launcher and before the game starts. A newer one from the API is kept. The Injector page shows the installed version.
  • Log page: Show console brings the console window of the mods to the front while the game runs - also when it was started with the "Console window" switch off. The window exists while it is hidden, so no restart is needed. The button calls swinject console show, which also works by hand and in scripts (show, hide, toggle, status). Needs injector 1.0.5 (Injector page).

1.0.10 - 2026-11-01#

Fixed#

  • Injector page: when the injector file was removed after the install (a virus scanner, os error 225), the page no longer says "installed and up to date". It says the file was removed and what to allow in Windows Security. The install checks the file again after a moment, and a start that fails with error 225 explains it.

1.0.9 - 2026-11-01#

Changed#

  • Links and the Steam start are opened with the Windows shell directly (ShellExecuteW) instead of through rundll32.exe and cmd.exe. Those two programs are used by malware to start things unseen, and a virus scanner can read such a start as suspicious behaviour.

1.0.8 - 2026-11-01#

Changed#

  • Settings, Injector and Log pages: grouped settings, a clear space at the top, buttons in the style of the Installed page.
  • Switches are green (#37a437) with a round knob that is centred.
  • Links that lead to the website open in your browser instead of the file explorer.
  • Mod icons with a transparent background are shown on a transparent background.
  • The mod log file starts anew with every run of the game (the old one is kept as stormworks_mods.old.log), so it shows what the console shows.
  • The embedded version patch (swversion.dll) scans the game faster and uses less processor time while the game loads.

1.0.7 - 2026-11-01#

Added#

  • Console window (Settings): a switch that hides the console window of the mods. The log is still written, so the Log page keeps showing everything. Applies the next time the game starts.

Changed#

  • Load delay: the default is now 5 seconds instead of 10 (a value you set yourself is kept). Comes with the injector of this version.
  • The embedded injector and version patch are rebuilt (injector 1.0.4).

1.0.6 - 2026-10-31#

Added#

  • Load order. Drag a mod in the Installed list to a new place. A mod lower in the list is loaded later and wins when two mods bring the same file, so a compatibility mod goes to the bottom. The order is saved in the launcher settings and is used for the mod folders (Data, Meshes, Graphics) and for the order in which DLLs are loaded when you press Play.
  • Discord (Settings): an optional switch that shows in your Discord profile where you are (main menu, a world, an editor), how many mods are on, and a Download and a Website button. Off by default; it starts with the game. It is part of the injected version patch, so it needs no mod.
  • Load delay (Settings): seconds the game must have run before code mods are loaded, 10 by default (5 since 1.0.7). Needs injector 1.0.2.

Changed#

  • Injector, Log and Settings pages: readable filter chips and a monospace log with level colours. Buttons keep the orange look of 1.0.4.
  • Mod asset zips may now contain shader files (.glslv, .glslf, .glslh). The Workshop files mod.xml and mod.png at the top of a zip are skipped instead of rejected.

Fixed#

  • Switches of enabled mods are green when they are on.
  • Links in mod descriptions open in the default browser (https only).
  • Installing the injector no longer fails with "file in use" (os error 32) when a swinject.exe is still running: the new file is swapped in by renaming.

1.0.5 - 2026-10-31#

Added#

  • Injector page: a status header (ready / update available / not installed) with a short list of checks.
  • Log page: filter the game log by All, Warnings or Errors.
  • Settings page: shows the launcher version and a Check for updates button.

Fixed#

  • The game log showed a blank line between every line.

1.0.4 - 2026-10-31#

Fixed#

  • The launcher update card now shows in the bottom right corner, like the other notifications; toasts move up while it is visible.

1.0.3 - 2026-10-31#

Added#

  • New notification cards: coloured stripe, icon and a close button. Errors stay on screen until they are closed.
  • New launcher update card ("Update now" / "Later", a progress bar while updating, "Try again" when it fails).

Fixed#

  • Launcher update no longer loses the installer. A downloaded setup is now started from the temp folder; before, it ran out of the install folder, uninstalled the old version and deleted itself.
  • Empty catalog message uses the full width, and "Load more" is hidden when nothing is found.
  • Mods that are switched off in the launcher are unloaded from a running game.

1.0.2 - 2026-10-31#

Changed#

  • Bump the launcher version to 1.0.2.

1.0.1 - 2026-10-31#

Fixed#

  • Project descriptions and changelogs in the launcher now render the same Steam-style formatting tags as the website, including headings, emphasis, lists, links and HTTPS images.

1.0.0 - 2026-10-29#

Changed#

  • New name: DeltaLauncher (program deltalauncher.exe, window title, texts). Version 1.0.0 everywhere; the game shows DeltaLoader 1.0.0, the network version of a modded client is DL-1.0.0.
  • Self-update from the admin upload. The launcher asks GET /v2/launcher/latest for the newest release, which an administrator uploads in the dashboard of the mods site; it is not listed on any public page. The project deltav-modding-launcher is still used when the server has no such release.
  • Updated for Stormworks 1.15.25 (the version patch looks for the text v1.15.25).

Fixed#

  • Asset folders follow the mod switches. Only the asset folder matching each enabled DLL stem is overlaid before launch; for example, enabling example.dll selects mods\example, and enabling both example.dll and volcanic.dll selects both matching folders.
  • English config filename. Mod autostart now uses activemods.ini. Existing modmenue.ini settings are still read when the new file does not exist; the next change writes the new filename.
  • A mod that is switched off is unloaded. The in-game mod menu (main_menu) watches activemods.ini: a switch that the launcher turns off unloads the mod from a running game within a second, a switch that is turned on loads it. Before, a mod that the menu had loaded stayed in the game ("use the in-game menu"), and with the mods off the menu could start them again.

Added#

  • Install from the website. The Install button on the mod site opens a short dialog and hands deltav://install?slug=... to the launcher. The scheme is registered for the current user at every start (the portable EXE therefore works without an installer). A second process forwards the slug to the running launcher over a loopback socket and exits. The launcher installs the latest version, switches to Installed and shows the new entry. The dialog includes the launcher download for a PC where the scheme is not registered yet.
  • The launcher updates itself. At start (and every 30 minutes) it asks the API for the newest version of the project deltav-modding-launcher (a tool with one .exe). A newer one is downloaded, checked against its SHA-256, swapped in for the running program (the old file becomes .old and is removed at the next start) and started. Settings -> Launcher updates turns the automatic part off; a banner with an Update launcher button appears instead. Development builds never replace themselves.
  • A mod with a newer version has its Update button in front of the on/off switch.
  • Islands. Browse has a Mods | Islands switch. Installing an island downloads its zip, checks the SHA-256 and the contents (only map.xml, tiles/, meshes/), unpacks it to modsmaps<name>, copies the tile and mesh files into rom without overwriting a game file, and switches the map on. The mod islands is installed and switched on with the first island. Installed islands have their own list with Update and Remove.

0.2.1 - 2026-10-23#

Added#

  • The version label is always in the game. The swversion.dll patch is embedded into the launcher and injected on every Play - with zero switched-on mods as well. It puts the built-in v1.15.23 64Bit / DeltaLoader alpha-0.1.0 display into the main menu. The DLL is written next to the downloaded swinject.exe, which also loads it before the first mod; the launcher and swinject check the module list, so it is never injected twice.

Changed#

  • Installed now has one on/off switch per mod instead of separate load/unload and autostart buttons. The switch writes modmenue.ini, the same file the in-game mod menu reads, so launcher and game always show the same state.
  • Play starts the game and loads exactly the mods that are switched on. If the game is already running, the switches are applied in place: mods that are now off are unloaded, new ones are loaded, and mods that are already in the game are skipped instead of being loaded twice.
  • The Play button carries the number of switched-on mods and its tooltip says what the next press will do.
  • Removing a mod asks in a dialog that follows the app style. The native WebView dialog (title tauri.localhost, system buttons) is gone.
  • The WebView context menu is disabled; text fields keep theirs so that copy and paste still work.
  • A mod that is switched on is copied into the game folder first, so a mod installed before the game folder was known is complete when it is switched on.
  • When the mod menu (main_menu/hauptmenue) is switched on, only it is loaded; it reads modmenue.ini and starts the other switched-on mods itself.

Fixed#

  • Play no longer ends in the Microsoft Store when the steam:// protocol is not registered. The launcher checks the association and, when it is missing, starts the executable from the configured game folder directly. Steam is also located through its SteamPath registry value, so a Steam or game installation outside drive C is found as well.
  • Folder opened Documents instead of the mod folder whenever the path contained a space - which the default game folder does. Explorer now gets /select,"<path>" as one raw argument.
  • A missing injector no longer stops the game from starting. The launcher starts it anyway and reports that the switched-on mods were not loaded.
  • Names in modmenue.ini without a matching DLL are reported as skipped instead of failing the launch.
  • Mods that the in-game menu loaded itself are named in the Play output instead of being silently ignored; the launcher cannot unload them.
  • The project type is no longer mixed into the category tags. Browse, project details and Installed now show a proper Mod, Tool or Shader badge, and the project dialog marks an installed project next to its title.

0.2.0 - 2026-10-22#

Changed#

  • The launcher contains no build tools. Mods and the injector are downloaded from the DeltaV mods API (Modrinth v2 shape), verified against the SHA-256 the API publishes and installed from there.
  • New Browse view: search, categories, sort order, project dialog with the version list and per-version install buttons.
  • Installed view: version display, update badge, "Check updates", autostart, deploy and remove. Manual DLLs in the game folder still show up.
  • New Injector page: installs and updates swinject.exe from the API project swinject. Only the downloaded injector is used.
  • Settings store the API address and the game folder.
  • Downloads land in %APPDATA%\DeltaVModdingLauncher\mods\<project id> and are tracked in installed.json, so updates survive a restart.
  • Distribution: a portable EXE on the mods site. No source code or mapping data is part of the download.

Removed#

  • CMake detection, build_mod, build_swinject and the "New mod" dialog. Building mods stays with native\build.ps1 and mods\dev.ps1.
  • Repo folder setting and detection, the local development build fallback, mapping check, game status and game path diagnostics.

Security#

  • Every download is rejected unless size and SHA-256 match the API answer.
  • File names from the API are validated before anything is written.

0.1.0 - 2026-10-20#

Added#

  • New name and appearance: DeltaV Modding Launcher with the DeltaV logo, its own Windows icon and DeltaV branding in the installer.
  • Revised UI with a narrow navigation rail, a status bar and a mod table.
  • Version display at the bottom left of the sidebar.
  • Settings: detect repo and game folder automatically, check the tools and build swinject directly from the launcher.
  • Build mods from mods\, load them into the running game and unload them, deploy them into the game folder and set autostart in modmenue.ini.
  • Mapping check, game status and game log directly in the launcher.

Fixed#

  • CMake is now also found in the Visual Studio Build Tools when it is not in the PATH. That way build swinject and mod builds also work with a plain Build Tools installation.
  • If CMake is really missing, a comprehensible message appears instead of program not found.
  • Vite no longer watches the Rust build folder; that removes the EBUSY aborts when rebuilding during development.
  • Native bridge built for x64 and x86; swinject reports 194/194 signatures.

Security#

  • The check stays fail closed: the SHA-256 and all signatures must pass, otherwise nothing is loaded.
  • Game files are not modified. The launcher only writes into native\build, into the game mod folder and into its own settings.
